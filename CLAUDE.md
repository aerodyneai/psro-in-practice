# CLAUDE.md — Build instructions for the psrolab companion repo

You are building the companion code for the book **"Policy-Space Response Oracles
in Practice"**. Every figure and table in the book is generated by a script in
this repo. The core skeleton (games/oracles/meta-solvers/loop/evaluator) already
exists, is tested, and its interfaces are FROZEN — extend, don't modify.

## Non-negotiable rules

1. **The loop is sacred.** `src/psrolab/psro.py` must stay under ~120 lines and
   must never gain variant-specific branches. Every PSRO variant is expressed as
   an `Oracle`, `MetaSolver`, `ProfileEvaluator`, or callback plugged into the
   existing `run_psro`. If a variant truly cannot be expressed that way (e.g.
   Pipeline PSRO's async population growth), create a SEPARATE loop file
   (`psro_pipeline.py`) rather than complicating the core one, and document in
   its docstring exactly which lines differ and why.
2. **Determinism.** Every experiment script takes `--seed` and is bit-reproducible
   for the numpy parts; torch parts must set all seeds and note any remaining
   nondeterminism in the script docstring. Figures in the book carry seeds.
3. **Tests before chapters.** Each new component ships with tests in `tests/`,
   and `pytest tests/` must pass with ONLY base deps installed (guard optional
   imports with `pytest.importorskip`). Never break the 5 existing smoke tests.
4. **Every experiment script is self-contained and boring.** Pattern:
   argparse → build components → `run_psro` → save metrics as CSV to
   `experiments/chXX/results/` → render figure(s) as PDF+PNG to
   `experiments/chXX/figures/`. No notebook-only results, ever. Notebooks may
   exist as optional walkthroughs but must import from the scripts.
5. **Honest measurement.** Wherever exploitability is plotted, the CSV column
   name must say which kind: `restricted_exploitability` (over the population)
   or `full_exploitability` (true game, via OpenSpiel's calculator). Mixing
   these up is the #1 sin of the PSRO literature and this book's whole pitch is
   not committing it.
6. **Compute budget discipline.** Part III comparisons run under a FIXED wall-
   clock or env-step budget, recorded in the CSV. A variant may only be declared
   better if better under equal budget. Every long-running script prints an
   estimated runtime at startup and supports `--smoke` (tiny config, <60s) so
   CI can execute every experiment path.
7. **Style.** ruff-clean, type-hinted, Google-style docstrings. Prefer plain
   numpy; keep torch code minimal and readable over fast. Reading order in a
   file: public API top, helpers below.

## Environment

- Python ≥3.10. `pip install -e ".[rl]"` for Part II+, `".[rl,distributed]"`
  for Part III ch. 10.
- Reference hardware for the book: single machine, 1–2× V100 (Part II) up to
  4 servers × 2 V100 (Part III). Everything must ALSO run CPU-only in `--smoke`
  mode. Auto-detect CUDA; never require it.
- OpenSpiel provides Kuhn/Leduc and the full-game exploitability calculator.
  Pin the version in pyproject once first used.

## Build order (work through these milestones sequentially; commit per milestone)

### M1 — Part I experiments (matrix games; no torch needed)
- `experiments/ch02_nash_from_scratch/`: solve RPS, Matching Pennies, and a
  3-strategy non-transitive game by (a) support enumeration, (b) the LP solver.
  Figure: strategy simplex with Nash marked.
- `experiments/ch03_fictitious_play/`: implement `FictitiousPlay` in
  `src/psrolab/baselines/fp.py`. Figures: FP converging on RPS (time-averaged),
  FP strategy oscillation trajectory; exploitability-vs-iteration curves.
- `experiments/ch04_double_oracle/`: PSRO-as-DO on random zero-sum matrix games
  of growing size (10..500 strategies). Figures: population size at convergence
  vs game size; exploitability vs iteration; effect of payoff noise
  (`MatrixGameSim(noise_std=...)`) on convergence — this motivates episode-count
  choices later.

### M2 — RL oracle + Kuhn poker (Part II core)
- `src/psrolab/games/openspiel_wrap.py`: adapt any 2p OpenSpiel game to
  `SimGame`. Policies get observation tensors + legal-action masks.
- `src/psrolab/oracles/tabular_q.py` FIRST: a tabular Q-learning oracle for
  Kuhn. Pedagogically vital — readers see an RL oracle with zero neural
  machinery. Test: PSRO+tabular oracle on Kuhn reaches full-game exploitability
  < 0.05 within 15 iterations.
- `src/psrolab/oracles/ppo.py`: minimal single-file PPO (~300 lines) training
  against `MixtureOpponent`. No stable-baselines dependency — the book prints
  this file. Test on Kuhn vs the tabular oracle's result.
- `experiments/ch06_ppo_oracle/`, `experiments/ch07_kuhn_leduc/`: exploitability
  curves for {uniform, Nash} × {tabular, PPO} on Kuhn; Nash+PPO on Leduc.
  Leduc is the first genuinely GPU-worthy run; give it `--smoke`.

### M3 — Meta-solver zoo (Ch. 8)
- `src/psrolab/meta_solvers/alpha_rank.py` (implement from the alpha-Rank paper;
  validate against open_spiel.python.egt.alpharank on shared test cases),
  `regret_matching.py` (CE/CCE via regret matching), `projected_replicator.py`.
- Experiment: same game + oracle, five meta-solvers, one figure. Include the
  runtime-per-solve table — practitioners need to know Nash-LP cost vs RM cost
  as populations grow.

### M4 — Variants under equal budget (Part III)
- `src/psrolab/psro_pipeline.py` + Ray actors for parallel BR training.
  Experiment: wall-clock speedup curve, 1/2/4/8 workers, Leduc.
- `src/psrolab/oracles/diverse_ppo.py`: PPO + behavioral-diversity bonus
  (implement the BD term from the PSD-PSRO / diversity literature; cite which
  paper's formulation in the docstring). Experiment: diversity on/off on (a) a
  transitive game, (b) a highly cyclic game — the book's point is that diversity
  pays only in (b).
- `src/psrolab/baselines/self_play.py`, `last_k_solver.py` for the self-play
  ablation.
- `experiments/ch12_shootout/`: the flagship table — all variants, Leduc + one
  matrix game, fixed budget, 5 seeds, mean±std final exploitability. This table
  sells the book; make it a script that emits both CSV and a LaTeX table.

### M5 — Capstone domain (Part IV)
- `src/psrolab/games/pursuit_evasion.py`: 2D continuous pursuit-evasion,
  1 pursuer vs 1 evader, zero-sum, ~10-dim observation, discrete 8-way + stay
  actions, episode cap. Pure numpy physics, no external sim. Deterministic given
  seed. Render top-down trajectory plots (matplotlib) — these become the book's
  most visual figures.
- Experiment: full PSRO (Nash + PPO) on pursuit-evasion; figures: exploitability
  proxy (population tournament), trajectory evolution across iterations
  (iteration 1 vs 5 vs 15 behavior), meta-strategy support over time.
- `experiments/ch14_engineering/`: payoff-table cache hit-rate measurement,
  checkpoint/resume demonstration (kill a run mid-iteration, resume, identical
  final table), profile-evaluation cost breakdown chart.

### M6 — Repo polish
- CI (GitHub Actions): ruff + pytest + every experiment in `--smoke` mode.
- `docs/figure_manifest.md`: table mapping every book figure number → script →
  command line → output file. This manifest is the contract with the manuscript.
- README quickstart verified from a clean venv.

## What NOT to do
- No frameworks (no stable-baselines3, no rllib for the core path; Ray core only
  for ch. 10 parallelism). The book's value is code readers can read.
- No silent hyperparameter tuning: every hyperparameter lives in the script's
  argparse defaults, and any tuning performed must be noted in
  `experiments/chXX/NOTES.md`.
- Do not add abstractions speculatively. Three concrete uses before an
  abstraction.
- Do not touch anything ITAR/defense-specific. The capstone is a generic,
  publishable pursuit-evasion toy.
